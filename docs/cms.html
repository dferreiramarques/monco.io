Editor de textos do monco.io

Um CMS mínimo instalado no próprio repositório: edita todos os textos do site (PT e EN) numa interface local, guarda no disco e publica no ar com um push de git — sem escrever código e sem gastar tokens de IA.

1 · Arrancar

Na pasta do projecto, corre (substitui o http.server antigo):

python dev.py

Depois abre http://localhost:4173/editor.html. O site continua acessível no mesmo endereço (http://localhost:4173/).

2 · O editor

  • Esquerda — todos os ~745 campos de texto, agrupados por secção (hero, cyc = o ciclo, m = método, spark / nimble / wave / ludens, eq = CV/pessoas, pj / r = produtos…). Cada campo mostra PT (texto claro) e EN (texto esverdeado) lado a lado. Os grupos fecham-se clicando no título; os campos alterados ficam com fundo destacado até serem guardados.
  • Procura — a caixa no topo filtra por chave ou por conteúdo (workshop, / 03…).
  • Direita — preview vivo do site com seletor de página; recarrega no ↻ ou muda de página. O idioma muda-se dentro do próprio preview (botões PT/EN do site).
  • HTML simples é permitido nos valores: <em>, <strong>, <br> — o mesmo que já está a ser usado.

3 · Guardar e publicar

  • Guardar (activa assim que há alterações) — grava assets/js/i18n.js no disco. O preview recarrega sozinho.
  • Publicar (git push) — pede uma mensagem de commit e executa git add -A → git commit → git push no repositório real. O GitHub Pages reconstrói monco.io em ±1 minuto. Se nada foi alterado, diz “Nada para publicar”.
  • Podes guardar várias vezes antes de publicar — cada Guardar é só no disco; o Publicar leva tudo o que estiver pendente.

4 · Segurança e reversões

  • Antes de cada gravação é criado um backup com data: assets/js/.i18n.AAAAMMDD-HHMMSS.bak. Ninguém os envia para o o git (estão no .gitignore).
  • Para voltar atrás: troca o nome do ficheiro .bak mais recente para i18n.js (apagando o actual ou renomeando-o primeiro) e clica ↻ no editor/preview.
  • No site publicado (monco.io/editor.html) o editor fica em modo leitura — sem servidor local não há API de gravação, por isso o site ao vivo nunca é alterado por ai.

5 · O que o editor não faz

  • Novos campos/chaves — edita o que já existe. Para uma nova secção ou campo extra, pede ao agente (1 frase basta).
  • Estrutura HTML — mover/mexer/adicionar secções, imagens ou botões: com o agente, por ser raro e delicado.
  • Os CVs imprimíveis (cv/pt.html, cv/en.html) têm o seu próprio HTML — não passam pelo editor.
